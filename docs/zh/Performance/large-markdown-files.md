# MarkFlowy 的大 Markdown 文档编辑

MarkFlowy 专注大 Markdown 文档的编辑响应。v0.100.0 更新说明记录了**一份 2 MB Markdown 文件在测试中约 1 秒打开**的结果。本文解释这一观察的范围，以及如何评估自己的文档；它不是一份新的基准测试报告或产品排名。

证据核对日期：2026 年 9 月 6 日。

## 已公开的信息

| 项目 | 已有信息 |
| --- | --- |
| 来源 | [v0.100.0 更新说明](https://github.com/drl990114/MarkFlowy/releases/tag/v0.100.0) |
| 文档大小 | 记录为 2 MB |
| 打开时间 | 测试中约 1 秒 |
| 背景 | v0.100.0 发布了编辑器重构，部分编辑行为发生变化 |
| 硬件、操作系统、文件内容与校验值 | 更新说明未提供 |
| 冷暖状态、样本数、P50/P95 与原始样本 | 更新说明未提供 |

这项观察不能解释为一秒打开的保证、P95 结果或所有操作系统具有相同表现的证明。后续版本也可能变化，比较时应记录版本。

## 为什么只看文件大小不够？

大小相近的 Markdown 文件可能具有不同结构，例如长段落、大量短块、表格、代码块、图片或图表。首次打开、模块加载后再次打开文件，以及切换到已有标签页，也是不同场景。

优先选择与你日常工作相似的文件，分别记录源码与可视化编辑模式的结果，并说明是否包含外部图片或图表。比较时保持文件、编辑模式、机器和应用状态一致。

## 如何比较自己的文件？

1. 下载桌面发行版，记录版本、操作系统、CPU、内存和编辑模式。
2. 记录文件大小与结构；能够公开时，保留校验值或可复现的测试文件。
3. 分别测量首次打开、重复打开、切换到已打开标签页。将“文档已显示且可编辑”定义为结束点。
4. 检查首次输入、滚动，以及有代表性的选区或复制操作。打开时间不能代表完整编辑体验。
5. 如果准备发布耗时分布，每个场景至少重复 30 次，保留慢样本和失败样本，并给出样本数、P50/P95 和原始记录。

录像可以提供粗略观察；精确结果需要一致的计时方式，并说明开始与结束时刻。手动计时与自动采集的结果不应混在同一分布中。

## AI 耗时单独记录

AI 请求涉及模型加载、必要时的网络传输和生成耗时。评估时记录服务商、模型和上下文大小；模型回答慢，本身不能证明编辑器打开或输入响应慢。

使用方式见[产品介绍](../intro)与 [Ollama 指南](../Extension/UseCopilotWithOllama)。如果某个文件表现较慢，可以[提交问题](https://github.com/drl990114/MarkFlowy/issues)，附版本、环境、场景和可分享的示例。
